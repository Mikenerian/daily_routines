# AI政策・戦略系イベント自動収集

## 目的
日本のAI政策・企業AI戦略・コンサルティング領域のイベントを定期収集し、参加価値の高いものをフィルタリングしてレポートを生成・Slack投稿する。

## 収集対象の条件
以下をすべて満たすものを優先する：
- 開催地：日本国内（リアル開催を優先、オンラインは懇親会ありのものに限定）
- 時期：今日から3ヶ月以内
- テーマ：以下のいずれかに該当
  - AI政策・規制・ガバナンス
  - 企業のAI戦略・経営レイヤーの意思決定
  - AIエージェント・生成AIの社会実装
  - DX推進・データ戦略

## 除外条件
- 純粋な技術ハンズオン（コーディング、モデル構築のみ）
- 特定製品のセールス色が強いウェビナー
- 懇親会のないオンラインのみのイベント

## 手順

### 1. 収集元ごとにWeb検索・フェッチ

以下の順番で収集する。各収集元に対して:
- 指定キーワードでWeb検索し、イベントURLを取得
- 各URLをフェッチしてイベントの詳細（名称・日程・会場・主催・参加費・懇親会有無）を抽出する

| 収集元 | URL / 検索キーワード |
|---|---|
| connpass | キーワード：「AI政策」「生成AI 戦略」「AIガバナンス」 |
| 日経イベント | https://events.nikkei.co.jp |
| AISI（AI安全研究所）| https://aisi.go.jp/activity |
| デジタル庁 | https://www.digital.go.jp/news |
| Peatix | キーワード：「AI 政策」「AI カンファレンス」 |
| xSUM（GenAI/SUM）| https://xsum.jp |

### 2. 条件フィルタリング・重複排除

収集したイベントに対して:
1. 開催日が今日から3ヶ月以内のものに絞る
2. 除外条件に該当するものを除く
3. 同一イベントの重複を排除する（URL・名称で照合）

### 3. 優先度ソート

以下の基準でカテゴリ分けする:
- **★ 最優先**：リアル開催 かつ 懇親会あり
- **◎ 次点**：オンライン かつ 懇親会あり、またはリアル開催で大規模カンファレンス（100名超）
- **△ 情報収集目的**：オンラインのみ（懇親会なし）

### 4. レポート生成・Slack投稿

イベントが1件以上あった場合のみSlackに投稿する。投稿フォーマット:

```
# AIイベント収集レポート｜{収集日}

## ★ 最優先（リアル開催・懇親会あり）
| イベント名 | 日程 | 会場 | 主催 | 参加費 | URL |
|---|---|---|---|---|---|

## ◎ 次点（オンライン・懇親会あり、またはリアルで大規模）
| イベント名 | 日程 | 形式 | 主催 | 参加費 | URL |
|---|---|---|---|---|---|

## △ 情報収集目的（オンラインのみ）
| イベント名 | 日程 | テーマ | URL |
|---|---|---|---|

## 収集メモ
- 収集日時：{収集日時}
- 検索クエリ一覧：{使用した検索クエリ}
- 次回収集推奨日：{収集日から4週間後}
```

イベントが0件の場合は Slack 投稿をスキップしてログ出力のみ行う。

`SLACK_WEBHOOK_URL` 環境変数が未設定の場合も Slack 投稿をスキップしてコンソールに出力する。

投稿は `curl` コマンドを使う:
```bash
curl -s -X POST "$SLACK_WEBHOOK_URL" \
  -H "Content-Type: application/json" \
  -d "{\"text\": \"...(メッセージ内容)...\"}"
```

### 5. ターミナル出力

実行完了後に以下をコンソールに出力する:
- 新規イベント件数（カテゴリ別）
- 最優先イベントの概要（名称・日程・会場）

## 注意事項
- ネットワークエラーが発生した収集元はスキップしてログ出力し、次の収集元の処理を続ける
- 日程・会場・懇親会の有無が不明なイベントは「△ 情報収集目的」に分類する
- イベント情報は正確さを重視し、センセーショナルな表現を避ける
- 新しいブランチを作成したり、PR を作成したりしない
